The assistant

02 · The project repository

<project name>-d365/

Unpacked solutions and source code. This is the tree that makes an agent grounded rather than plausible.

Owner
The team — shared, PR-reviewed
The assistant
Reads and writes — it builds here
03 · Live documentation

<project name>-wiki/

A wiki backed by git is a surface the assistant can read and write, not a browser-only one. A push is a publication.

Owner
Everyone — the wiki's own review flow
The assistant
Drafts; a human edits and publishes
The point: one prompt is able to span all three
Read the story in <project name>-Context/1234-*, check it against the solutions in <project name>-d365/solutions/ and the source code, and tell me which wiki pages under Functional/ will need updating.

The assistant works across all three, reading what it needs — no re-explaining, no pasted screenshots.
