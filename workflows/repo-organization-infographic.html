Laying them out on disk
Clone all three as siblings under one parent folder, then make all three visible to the assistant at once.
<client>/
├── <client>-Context/   Intent + plans
├── <client>-d365/      Solutions + code

VS Code / Cursor

A multi-root workspace (<client>.code-workspace) with the three folders as roots.

Claude Code

Add the other two as additional working directories, so it reads them without leaving the project repo.

Either way

Open the parent folder if the tooling supports it, so relative paths between the repos stay stable in prompts and scripts.

One prompt can span all three
Read the story in <client>-Context/1234-*, check it against the solutions in <client>-d365/solutions/ and the source code, and tell me which wiki pages under Functional/ will need updating.

The assistant works across repositories, reading what it needs.

Which repository answers which question
When the agent needs to know something, this is where it looks — and how.
QuestionRepositoryRead via

Boundaries between them
Placement decisions and hygiene rules, all of them expensive to change later.

The zips stay out of git

The unpacked solutions/<Name>/src/ tree is the reviewable source of truth; the .zip is a rebuildable artifact.

Web resources flow one way

Authored in webresources/ and deployed into the solution. Considered as source code.

Each repo has its own trigger

Packs refresh on a re-export, the solution tree on every export/unpack, the wiki when behaviour changes.

Personal material

Story mirrors, drafts and notes stay in <client>-Context/. What graduates into <client>-wiki/ does so deliberately, reviewed.
